# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static documentation site generated by a small Go program in this repository (`tools/docsite`): goldmark renders the Markdown in `docs/` into bespoke HTML and CSS templates; GitHub Actions publishes the output to GitHub Pages. No Node toolchain. (Confirmed by the maintainer.)

## Users

Software engineers who already use the GitHub Copilot app and want to ask a colleague's agent a question from their own session. Two situations: the person evaluating Wormhole for their team (reads the home page, the design, the security model, then installs), and the person who has it running and needs one answer fast (a CLI flag, a config key, a daemon behavior). Both read on a laptop in an IDE-adjacent context; many keep dark editors, some read on a phone.

## Product Purpose

Wormhole lets `ask ^bob what he thinks about X` in any Copilot session deliver that question into a new session on Bob's machine and bring his answer back. One Go binary (CLI plus daemon), a NATS JetStream bus behind an interface, and a skill that teaches agents the `^handle` syntax. The docs exist so a team can deploy it privately, understand its safety model, and operate it. Success: an engineer can go from the home page to a working round trip between two machines using only the docs.

## Positioning

Agent-to-agent asks across machines with the sender bound by the bus subject and enforced by the server, inbox mode by default so a person reads inbound text before any tool runs, and no hosted service: every team runs its own bus from shipped templates. A thread is an open wormhole; `ask` opens one, `reply` travels back through it.

## Operating Context

Documentation lives as Markdown under `docs/` and is the source of truth; the site renders it. Pages today: index (home), install, usage, design, roadmap, m0-spike, and the skill text (generated from `skills/wormhole/SKILL.md`). Releases are tagged on GitHub with Linux tarballs and checksums; the site links to them and shows the current release tag. Readers arrive from the GitHub README and from release notes.

## Capabilities and Constraints

- Static output only; no server-side search. Client-side search over a generated index is acceptable.
- Deployed at https://yjmrobert.github.io/wormhole/ under a subpath, so every asset and link must be relative or prefixed.
- Fonts and scripts are self-hosted; no third-party requests at runtime (the binary never phones home, and the docs follow the same rule).
- Linux-only product for now; macOS and Windows arrive in M4. Pre-1.0: the M0 spike has not been run on real machines, and the docs say so.
- Placeholder names only: `alice`, `bob`, `bus.example.internal`, `<owner>/<repo>`. Nothing that identifies a deployment.
- Terminology: handle, thread, ask, reply, send, inbox mode, auto mode, daemon (`wormholed`), bus, envelope, hop, receipt (ack), dead letters.

## Brand Commitments

Name: Wormhole. The maintainer pinned the visual world for the docs in October 2026: synthwave, a 1984 night in cyan, magenta and violet on deep navy, with physics pictures of the wormhole (a floor bent into a well under a striped wormhole on the horizon). Dark is the native theme; a light theme stays available. Ambient motion is welcome on the home page as long as it stays cheap: nothing computed at runtime, one or two transform animations, the reading column calm. The wordmark is a neon sign (Monoton) over a drawn mark.

## Evidence on Hand

- Real content: everything under `docs/`, `README.md`, `SECURITY.md`, `skills/wormhole/SKILL.md`, the deploy templates.
- Real artifacts: the v0.1.0 release and its checksums; the test suite proving the round trip over NATS.
- Absent, never to be fabricated: user testimonials, adopter names, benchmarks, a hosted demo, macOS or Windows support claims.

## Product Principles

- The reader's question comes first: structure for comprehension, then make the frame worth staying in.
- Say what is proven and what is not; the M0 spike is unrun and the docs never imply otherwise.
- Private by construction: the docs never name a real deployment, and the site makes no third-party requests.
- One toolchain: Go builds the binary and the site; a contributor needs nothing else.
- The world lives in the frame (masthead, rail, ground, openers, code and table styling); the column stays calm.

## Accessibility & Inclusion

WCAG AA contrast in both themes; every animation has a `prefers-reduced-motion` path that keeps state and hierarchy; keyboard-navigable rail and in-page contents; semantic headings and landmarks; the schematic diagrams carry text alternatives.
